# ARCHITECTURE.md

## Module map (Gradle Kotlin DSL, version catalog `gradle/libs.versions.toml`)

```
:app              Compose UI, navigation, ViewModels            (com.android.application)
:core:model       domain entities (pure Kotlin JVM)             Project/ChatMessage/ProviderConfig...
:core:engine      bolt.diy engine port (pure Kotlin JVM)        BoltStreamParser, ArtifactRunner,
                                                                CommandTranslator, DiffEngine,
                                                                PathSanitizer, ZipCodec,
                                                                SystemPromptFactory, ContextBuilder,
                                                                PreviewHarness, ProjectTemplates
:core:ai          provider adapters (pure Kotlin JVM)           OpenAiCompatibleClient,
                                                                AnthropicClient, GeminiClient,
                                                                Sse, ProviderClientFactory
:core:android     Android data/runtime (Android library)        Room DB, KeystoreCrypto,
                                                                RealProjectFileSystem,
                                                                StaticPreviewServer, repositories,
                                                                ChatSession, AppGraph (manual DI)
```

Pure-JVM modules keep the ported bolt.diy logic platform-independent and unit-testable
without Robolectric; the Android library implements the interfaces those modules define.

## Clean architecture flow

```
UI (Compose screens)
   ↓ state
ViewModels (app/vm)  ── repositories (core:android/repo)  ── Room / DataStore / files
   ↓ commands
ChatSession (core:android/session)
   ↓ provider stream
ProviderClient (core:ai)  →  StreamEvent.Token
   ↓ tokens
BoltStreamParser (core:engine)  →  artifact/action callbacks
   ↓ actions
ArtifactRunner (core:engine)  →  ProjectFileSystem (core:android impl)
   ↓ before/after content
DiffEngine (core:engine)  →  diff UI, revert
```

## The engine pipeline (per assistant message)

1. `ChatViewModel` builds `ChatSession` with the default provider's runtime config
   (key decrypted in memory only).
2. User text + `ContextBuilder` file map go out as one request; the system prompt
   comes from `SystemPromptFactory` (ported bolt.diy contract, Android constraints).
3. `ProviderClient.streamChat` (OkHttp + hand-written SSE) emits `StreamEvent.Token`s.
4. Every token appends to the accumulated message; `BoltStreamParser.parse(messageId, full)`
   (the upstream contract: full text + internal cursor) emits artifact/action events.
5. `onActionClose` → `ArtifactRunner.applyFileAction` (mkdir parents + write full content,
   keeping before/after for diff/revert) or `applyShellAction` (CommandTranslator whitelist
   → FS effects; npm → recorded; unsupported → FAILED action with human-readable note).
6. On completion the message is persisted (prose + `ArtifactSummary` records) in Room;
   the project type is re-inferred from the file set.

## Preview runtime

`StaticPreviewServer` (raw ServerSocket, 127.0.0.1-only, GET/HEAD, MIME-mapped,
path-sanitized) serves the project directory. Static projects load `index.html`
directly. React/TSX projects load `/__preview__`, a page generated by
`PreviewHarness` that fetches sources from the server, transpiles with
@babel/standalone (CDN), resolves bare imports via an esm.sh import map built from
package.json, and executes the module graph with a CommonJS shim. Console + errors
flow back through a WebView JS bridge into a bounded ring buffer (see
ANDROID_RUNTIME.md).

## Persistence

- `projects/` Room table + one directory per project under `filesDir/projects/<id>`.
- `messages` Room table (chat history incl. artifact summaries).
- `providers` Room table (API keys only as Keystore-encrypted ciphertext).
- Preferences in DataStore (theme, fonts, autosave, last project).

## Threading & memory

- Provider streams collect on `Dispatchers.IO`; session state via `StateFlow`
  (thread-safe) — UI recomposes from a single source of truth.
- Debounced autosave (700 ms), bounded undo stacks (200 snapshots),
  highlight cap at 120 KB, console ring buffer (300 lines), context builder
  capped at 48 KB — all per brief §24 (4–12 GB RAM targets).
