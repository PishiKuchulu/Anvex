# BoltDroid v4.2.2 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify and harden the BoltDroid v4.2.1 tree into a shippable v4.2.2 with zero new features.

**Architecture:** Verify-first sequencing — repair the audit tooling on Windows, then let the real compiler and test suites dictate every fix. Static review is deliberately limited to the v4.0→v4.2.1 delta (~30 real sources, zip dates ≥ 2026-09-29, mirror copies excluded) because v4.0 shipped behind a real Gradle build. Release packaging reuses `git archive` so the ZIP is byte-identical to the committed tree.

**Tech Stack:** Kotlin 2.0.21 / AGP 8.7.3 / Gradle 8.10.2 / JDK 17 / Room schema v12 / Python 3 stdlib-only audit tools.

## Global Constraints

- No new features, no UI redesign, no refactors beyond what the compiler/tests force.
- All Kotlin fixes are behavior-preserving; Room schema stays at v12 — never fabricate schema snapshots, only a real KSP build may regenerate them.
- Audit tools stay stdlib-only Python 3, Windows- *and* POSIX-compatible.
- `local.properties` (SDK path) is machine-local and must never be committed.
- Commit after every task; one concern per commit.
- Working directory for all commands: `E:/4/BoltDroid/worktree-v4` (repo root, git `main`).
